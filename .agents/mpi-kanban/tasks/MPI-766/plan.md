### Decisions settled here (not Fabio's forks)

- **One new shell module, `js/shell/heroCrew.js`**, the twin of `heroQuote.js`: `initHeroCrew()`
  is called once from `js/shell.js` boot, subscribes to `currentPage`, and mounts / destroys the
  crew. It holds the roster (key, name, role line, accent token) and is the ONLY code that knows a
  mascot file path: `assets/mascot/<key>/<pose>.webp`. The animated WebM loops later replace that
  one function. MPI-708's media-type map is a different thing (media type -> character) and is
  not built here.
- **Stage scaling: one unit, pure CSS, read off the VIEWPORT.** The crew layer is a 1120x1000
  box, bottom-centred, scaled by `--crew-k = min(100vw / 1920px, (100vh - titlebar) / 1000px)`
  (the hero is 7/12 of the window). No ResizeObserver, nothing to tear down. Plan Drift says why
  it is not a size container.
- **Hit testing.** The crew layer sits under `.mpi-landing__hero-inner`, which takes
  `pointer-events: none` with the nav re-enabled, so the headline stays above the crew visually
  and the crew still gets hover and click.
- **Family tokens go in `styles/01_base.css`**, beside `--accent-audio`, with the MPI-736 table's
  values: `--hub-accent`, `--vision-accent` (the pink as a literal, NOT `var(--accent-heat)`: when
  MPI-736 turns the landing's action token to ink, Vision's dot must stay pink), `--prompt-accent`,
  `--video-accent`. Audio reads the existing `--accent-audio`. Renaming the family is MPI-736's.
- **Headline colours are untouched.** "Own it." keeps reading `--accent-heat`, so the hero ships
  in today's pink and flips when MPI-736 lands. The no-hue look also dims "Generate. Refine." to
  `--ink-3`; that belongs to MPI-736's landing flip, not here.
- **Entrances animate transform only**, with `backwards` fill, so a delayed member waits offset but
  visible. The light and pool are the only opacity fades.

## Plan Drift

- 2026-09-15: **The headline scales with the stage.** At 950x500 the 96px headline and the quote
  ran into the crew and pushed the stats off the hero, so the h1 size, headline top padding, quote
  size and quote width multiply by `--crew-k` (the quote floored at `--t-sm` and 260px). The
  crew labels are counter-scaled so the names stay 15px.
- 2026-09-15: ~~Two breakpoints (role lines out below ~0.87, crew out below 0.7).~~ **Replaced
  after Fabio's look:** on his 1280x976 monitor the crew vanished although the hero had plenty of
  height, because the hide keyed on a width-limited scale. Now the crew SCALES to the room it has:
  the floor stays 160px above the hero's bottom (labels and stats always fit), and `_fit()` in
  heroCrew.js sets `--crew-k` from a ResizeObserver so Vision's head clears the quote and Studio's
  clears the headline. Labels drop out only when they would collide side by side (role lines below
  0.66, names below 0.41, from measured label widths); the crew hides only below 0.25.
- 2026-09-15: **Not a size container.** With `container-type: size` on the hero, ANY text change
  inside it (quote or stats) restarted every crew entrance animation: `getAnimations()` showed 5
  running at currentTime ~40ms after a stats edit, and 0 with the container removed. A separate
  container frame around the crew restarted them too. heroStats repaints that foot while a Pod is
  connected, so the crew would have kept re-entering. `--crew-k` now reads the viewport and the
  breakpoints are media queries.
- 2026-09-15: **The entrance waits for a clear screen, as a reusable signal** (Fabio). The crew
  mounted at `initShell`, before `_bootApp` had even checked the engine, so its entrance played
  behind the engine gate, the 18+ notice and the changelog. `state.screenClear`
  (`js/shell/screenClearService.js`) is false until `shell:booted` (emitted by `_bootApp` after
  those dialogs) and whenever the `Overlays` stack is non-empty or a backdrop sits on `<body>`
  (`MpiStartingComfy` bypasses `Overlays`). It is state rather than an event so a late mount reads
  it. It recomputes on the next animation frame: a microtask version reported a false `true`
  in the one frame between the 18+ notice closing and the changelog opening (MPI-333 defers
  that open). The crew holds with `animation-play-state: paused`, which never restarts an animation.
- Pre-existing, not this card: at 950px wide the hero top bar wraps (version over nav) and the
  stats foot wraps.
